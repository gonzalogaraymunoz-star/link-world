# LINK · Arquitectura canónica del organismo económico v1

**Estado:** canónico  
**Versión:** 1.0.0  
**Fecha:** 2026-10-06  
**Ámbito:** LINK WORLD / LINK Director / GENESIS / LINK WORLD GAME

> LINK detecta dolores reales, explora soluciones, convierte las soluciones válidas en modelos y artefactos, formaliza negocios cuando existe evidencia económica y operativa, y reutiliza lo aprendido para resolver nuevos dolores.

## 1. El origen es el dolor

El negocio no es el punto de partida.

```text
DOLOR
  ↓
HOBBY / EXPLORACIÓN
  ↓
SOLUCIÓN
  ↓
MODELO
  ↓
ARTEFACTOS
  ↓
NEGOCIO
```

El **dolor** es una fricción real del mundo. LINK debe poder detectar:

- qué duele;
- a quién le duele;
- cuánto vale resolverlo;
- qué modelos existentes pueden servir;
- qué falta construir.

## 2. Antes del negocio existe el hobby

El hobby es el espacio de exploración. Aquí LINK puede observar, conversar, prototipar, probar, equivocarse y aprender sin comprometer todavía la estructura completa del ecosistema.

Una exploración cruza el umbral de negocio cuando existe suficiente evidencia de:

```text
PROBLEMA REAL
+
SOLUCIÓN VALIOSA
+
CLIENTE O DEMANDA
+
FLUJO REPETIBLE
+
LÓGICA ECONÓMICA
+
CAPACIDAD DE OPERACIÓN
=
NEGOCIO
```

La decisión de comprometer capacidad del sistema pertenece a **LINK Director**.

## 3. La concha LINK

Cuando una solución se transforma en negocio entra a una estructura de doble articulación.

```text
                         LINK DIRECTOR
                    ╭────────────────────╮
                    │                    │
                    ▼                    ▼
       MAR — VENTAS — CIERRE — BOARDING — OPERA — POSTVENTA
        ▲       ▲        ▲        ▲         ▲         ▲
        │       │        │        │         │         │
        ╰───────┴────────┴────────┴─────────┴─────────╯
                     LINKDOT DEL NEGOCIO
                            ↕
                        ARTEFACTOS
                            ↕
                          MODELOS
```

La idea esencial es que **Dirección se abre hacia las seis áreas desde arriba y el negocio se abre hacia las mismas seis áreas desde abajo**.

Las seis áreas son puntos de articulación entre dos inteligencias:

- **Dirección:** criterio global, prioridades, recursos, límites y objetivos.
- **Negocio:** realidad específica, clientes, oferta, precios, reglas, capacidad, operación y resultados.

## 4. Las seis áreas transversales

Las seis áreas del sistema son:

1. **MAR** — conversación, relación, escucha y conducción del interés.
2. **VENTAS** — transforma necesidad en propuesta comercial.
3. **CIERRE** — convierte decisión en compromiso comercial y transacción válida.
4. **BOARDING** — transforma la venta cerrada en un caso ejecutable.
5. **OPERA** — entrega y cumple la solución en el mundo real.
6. **POSTVENTA** — verifica resultado, continuidad, satisfacción y nueva oportunidad.

Estas áreas no pertenecen a un único negocio. Son capacidades horizontales del ecosistema.

## 5. Cada negocio tiene un LINKDOT responsable

Cada negocio tiene un **LINKDOT de negocio** que representa su funcionamiento completo dentro de LINK.

El LINKDOT del negocio conoce o sabe localizar:

- modelo económico;
- productos y servicios;
- precios y condiciones;
- disponibilidad;
- políticas;
- capacidades;
- artefactos;
- personas y proveedores;
- restricciones;
- historial y evidencia.

Una capacidad transversal no debe inventar conocimiento específico del negocio. Debe consultar al LINKDOT del negocio.

Ejemplo:

```text
MAR
 ↓ pregunta
LINKDOT LAMA
 ↓ consulta
ARTEFACTOS / DATOS / SUBDOTS
 ↓ devuelve contexto fiable
MAR
 ↓
CONVERSACIÓN CON EL LEAD
```

Así, **MAR es especialista en conversar y vender; el LINKDOT LAMA es especialista en Lama**.

## 6. Los artefactos son memoria ejecutable

Los artefactos son objetos concretos que permiten al negocio funcionar:

- conversaciones;
- catálogos;
- formularios;
- cotizadores;
- contratos;
- calendarios;
- CRM;
- bases de datos;
- pasarelas;
- listas;
- procedimientos;
- documentos;
- automatizaciones;
- aplicaciones;
- evidencias.

El LINKDOT no debe memorizar copias arbitrarias de la realidad. Debe saber dónde está el artefacto responsable.

## 7. De los artefactos nacen modelos

Cuando una forma de resolver un problema demuestra que funciona, LINK puede abstraerla.

```text
EXPERIENCIA REAL
   ↓
ARTEFACTOS
   ↓
RESULTADO
   ↓
APRENDIZAJE
   ↓
MODELO REUTILIZABLE
```

El modelo puede dejar de pertenecer al negocio que lo originó.

Por ejemplo, una venta turística puede revelar un modelo transversal de:

```text
lead → escucha → asesoría → propuesta → objeciones
→ decisión → datos faltantes → cierre → boarding → operación
```

LINK puede reutilizar ese modelo en otro negocio sin copiar el negocio original.

## 8. LINK no clona negocios: clona y combina modelos

```text
MODELO A ─┐
MODELO B ─┼─→ NUEVA SOLUCIÓN
MODELO C ─┘
```

El sistema puede resolver un nuevo dolor combinando capacidades ya aprendidas.

La unidad de reproducción de LINK no es el negocio completo. Es el **modelo verificable y reutilizable**.

Cada vuelta debe aumentar el patrimonio operativo del ecosistema.

## 10. LINK Daemon

El organismo necesita circulación permanente. **LINK Daemon** no es una séptima área: es el ciclo persistente que mantiene viva la relación entre Director, áreas, negocios, artefactos, modelos y mundo real.

```text
OBSERVAR
   ↓
COMPARAR
   ↓
DETECTAR
   ↓
ACTIVAR
   ↓
VERIFICAR
   ↓
APRENDER
   ↓
VOLVER A OBSERVAR
```

El daemon busca:

- dolores;
- desviaciones;
- bloqueos;
- oportunidades;
- decisiones pendientes;
- artefactos faltantes;
- modelos insuficientes;
- aprendizajes reutilizables.

Escala a LINK Director solo cuando la decisión realmente requiere dirección.

## 11. Dos loops conviven

### Loop operativo

Mantiene un negocio existente funcionando:

```text
LINK DIRECTOR
↕
6 ÁREAS
↕
LINKDOT DEL NEGOCIO
↕
ARTEFACTOS
↕
RESULTADO
```

### Loop reproductivo

Genera nueva capacidad económica:

```text
DOLOR → SOLUCIÓN → MODELO → NEGOCIO
→ APRENDIZAJE → MODELOS → NUEVO DOLOR
```

LINK Daemon mantiene ambos loops circulando.

## 12. LINK WORLD GAME

LINK WORLD GAME representa esta arquitectura con datos reales. No premia tareas por sí mismas; muestra patrimonio económico y autonomía construidos.

La condición económica global es:

> **Aumentar el ingreso mensual del ecosistema mientras disminuyen las horas del Director necesarias para producirlo.**

Métrica central propuesta:

```text
PODER LINK =
INGRESO NETO MENSUAL
───────────────────
HORAS DEL DIRECTOR
```

El juego también debe representar aumento de:

- negocios recurrentes;
- margen;
- autonomía;
- capacidad de ejecución;
- modelos reutilizables;
- territorio/red;
- problemas reales resueltos.

## 13. Principios canónicos

1. **El dolor precede al negocio.**
2. **Antes de comprometer estructura existe exploración/hobby.**
3. **Director y negocio se articulan simultáneamente con las seis áreas.**
4. **Cada negocio tiene un LINKDOT responsable.**
5. **Las áreas transversales consultan al LINKDOT del negocio para obtener verdad específica.**
6. **Los artefactos contienen la realidad ejecutable.**
7. **Los modelos se extraen de resultados verificados.**
8. **LINK reutiliza modelos; no copia ciegamente negocios.**
9. **LINK Daemon mantiene el feedback continuo.**
10. **La realidad corrige a Dirección y Dirección vuelve a actuar sobre la realidad.**

## 14. Fórmula central

```text
DOLOR
→ HOBBY / EXPLORACIÓN
→ SOLUCIÓN
→ MODELO
→ ARTEFACTOS
→ NEGOCIO
→ 6 ÁREAS
→ RESULTADO
→ APRENDIZAJE
→ MODELOS
→ NUEVAS SOLUCIONES
```

Gobernado por **LINK Director**, ejecutado mediante los **LINKDOT de área y de negocio**, y mantenido en circulación por **LINK Daemon**.
